# 路径一致候选语义人工审计指南

## 1. 目标与边界

人工审计只回答：路径一致但未被选中的候选，对给定问题与答案是否提供语义上有用的证据。它不参与 λ 选择，也不改变 test 结果。代码不能替代标注者，LLM 标签不能写成“人工审计”。

## 2. 抽样

从 11 个领域的历史逐题 audit JSONL 等额抽样，固定随机种子。每个问题最多抽一个候选，避免少数高冲突问题主导样本。抽样脚本输出两个独立乱序版本，不暴露模型分数或实验结果。

推荐至少每领域 20 个候选，共 220 个；若人力不足，先做每领域 10 个的 pilot，并在报告中明确置信区间较宽。

## 3. 标签

每名标注者独立填写：

- `relevant`：该候选事实直接支持答案路径，或提供完成该问题不可缺少的中间关系；
- `irrelevant`：虽然结构上位于某条答案最短路，但其语义关系与问题要求不符；
- `unclear`：仅凭给定实体/关系无法可靠判断，或事实本身含歧义。

同时填写 `confidence`（1--3）和一句简短 `rationale`。不得根据“算法认为它路径一致”倒推为 relevant。

## 4. 标注过程

1. 两名标注者先共同阅读本指南，但不共同标注。
2. 独立完成 pilot，讨论指南歧义，只修改规则，不修改已经看到的单条标签。
3. 重新独立标注正式样本。
4. 脚本计算原始一致率和 Cohen's kappa，并导出分歧条目。
5. 分歧由第三人或两人讨论形成 `consensus_label`；代码不自动多数表决。

## 5. 报告

至少报告抽样框、领域配额、两名标注者、各标签比例、原始一致率、kappa、分歧处理规则与有效样本数。语义相关比例只能解释为该抽样框内的估计，不能把它外推为所有路径一致候选都是真正正例。
