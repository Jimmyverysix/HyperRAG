# Candidate Oracle 分析

## 问题

Candidate Oracle 回答：在固定 beam=32、完全不读取答案生成的候选池中，有多少测试问题已经包含至少一条完整主题—正确答案路径？它只区分“候选池缺失”与“候选存在但排序靠后”，不训练新模型、不修改 beam，也不用于选择方法。

## 结果

- 测试问题：88,073；
- 候选池内存在完整答案路径的问题：31,128；
- micro Candidate Oracle Reach：35.34%；
- 11 领域等权宏平均：32.73%。

## 解释

在当前候选接口下，64.66% 的测试问题连完整答案路径都没有进入池中，因此任何只重排现有候选的 Retriever 都不可能在这些问题上取得非零 APC-MRR 或 Reach@k。当前绝对检索指标同时受候选生成上限和排序质量影响，不能把低绝对 APC-MRR 全部归因于 MLP 排序失败。

不同领域的上限差异很大：infra 为 58.77%，sport 只有 14.65%。这也解释了逐领域效应的可提升空间并不一致。Candidate Oracle 不是策略3的成绩，也不是一个可与 APC-MRR 直接相减的“剩余误差”。

## 为什么不继续扩大 beam

beam=32 在正式 lambda sweep 前由 art/valid 与 beam=10 的候选覆盖比较冻结。继续在 test 上尝试 64、128 或 256 会把诊断变成测试集调参，并改变所有方法共享的候选接口，因此本轮没有这样做。
